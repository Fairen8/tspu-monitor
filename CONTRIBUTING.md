# Как участвовать в разработке

Проект открытый; этот документ описывает правила для участников.
Участвуя, вы соглашаетесь соблюдать
[Кодекс поведения](CODE_OF_CONDUCT.md).

## Окружение разработчика

```bash
git clone https://github.com/Fairen8/tspu-monitor.git
cd tspu-monitor
python3 -m venv .venv
. .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

Проверки:

```bash
ruff check src tests         # линтер
pytest -q                    # быстрые тесты (без сети)
pytest -q -m integration     # локальные интеграционные тесты проб
```

Для запуска реальных проверок сети скопируйте `config/secrets.yaml` в
рабочий каталог, заполните цели и выполните `tspu-monitor check --samples 1`.
Тесты, требующие интернета, помечены маркером `network` и по умолчанию
исключены.

## Стиль кода

* Python 3.11+, полные аннотации типов.
* Линтер: **ruff** (настройки в `pyproject.toml`); форматирование — `ruff format`.
* Docstrings и пользовательские сообщения — на русском; идентификаторы — на английском.
* Без комментариев-шума: комментарий объясняет «почему», а не «что».
* Долгие операции — асинхронные; блокирующие вызовы — через executor.

## Ветки и коммиты

| Ветка | Правила |
|---|---|
| `main` | разработка; изменения только через PR, обязательны зелёные CI и review |
| `release` | стабильные релизы; только PR из `main`, прямые коммиты запрещены |

* Рабочие ветки: `feat/<кратко>`, `fix/<кратко>`, `docs/<кратко>`,
  `chore/<кратко>`; PR — в `main`.
* Релиз: версия готовится на `main` (`scripts/release.sh`), затем PR
  `main → release`; после мержа релиз публикуется автоматически.
* Формат коммитов — Conventional Commits:

```
feat(probes): добавить пробу DoT
fix(classification): не считать молчание WG блокировкой
docs: описать релизный процесс
```

## Pull Request

Чеклист (продублирован в шаблоне PR):

* [ ] Тесты добавлены/обновлены, `pytest -q` зелёный.
* [ ] `ruff check src tests` без ошибок.
* [ ] Публичное поведение описано в `DOCS.md`, изменения — в `CHANGELOG.md`.
* [ ] Секретов и реальных IP в коммите нет.

## Добавление проб и сценариев

Пошаговые инструкции и контракты интерфейсов — в `DOCS.md`
(разделы «Пробы», «Сценарии», «Разработка»). Кратко:

1. Проба: класс-наследник `BaseProbe` в `src/tspu_monitor/probes/`.
2. Сценарий: файл в `src/tspu_monitor/scenarios/custom/` (без ведущего
   подчёркивания) с классом-наследником `BaseScenario`.
3. Тесты: юнит-тесты парсинга + интеграционный тест на локальном
   мок-сервере (без интернета).

## Безопасность

* Никогда не коммитьте `secrets.yaml` с реальными значениями.
* Уязвимости — через Private Vulnerability Reporting (см. `SECURITY.md`),
  не через публичные issues.
* Новые зависимости добавляйте только после оценки необходимости и
  размера; фиксируйте нижнюю границу версии.
* Установите pre-commit: `pre-commit install` — коммит автоматически
  проверяется ruff и gitleaks (утечки секретов).

## Релизы

Релизный процесс (версионирование, changelog, теги, артефакты) описан в
[`.github/REPO_SETUP.md`](.github/REPO_SETUP.md). Подготовка релиза
автоматизирована: `scripts/release.sh <версия>`.
